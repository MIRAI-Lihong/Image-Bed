# 技术总结：image-bed 图床是怎么做的

> 面向自己的技术讲解文档。读完你应该能回答：这个项目的每一部分是什么、为什么这样设计、数据怎么流动、安全边界在哪里、出了问题去哪里查。

## 一、一句话概括

一个无服务器的个人图床：浏览器从 Netlify Function 领取阿里云 STS 临时凭证（15 分钟有效、仅允许上传到指定前缀），然后**直传**阿里云 OSS，拿到公共读 URL 供博客引用。长期密钥永远不离开服务端。

## 二、核心概念扫盲

| 概念 | 是什么 | 在本项目中的角色 |
|---|---|---|
| **OSS** | 阿里云对象存储，按量付费的文件仓库 | 存图片，Bucket `mirai-image-bed`（深圳，公共读） |
| **RAM** | 阿里云访问控制，管理"谁能做什么" | 一个 RAM 用户（持有长期 AK）+ 一个 RAM 角色 |
| **STS** | 安全令牌服务，用长期身份换短时凭证 | Function 调用 STS `AssumeRole` 换取 900 秒临时凭证 |
| **AssumeRole** | "扮演角色"：RAM 用户临时获得角色的权限 | 角色 `image-bed-uploader` 只有 `oss:PutObject` 且限定前缀 |
| **Netlify Functions** | 托管在 Netlify 的无服务器函数，按请求触发 | 唯一的"服务端"：`POST /api/upload-credentials` |
| **CORS** | 浏览器跨域限制：页面所在域 ≠ 请求目标域时需目标域放行 | OSS Bucket 必须配置允许 Netlify 域名，否则浏览器拦截 PUT |
| **公共读 Bucket** | 任何人可读、不可写 | 图片 URL 可永久直接访问，适合博客外链 |

**为什么要绕 STS 这一圈？** 前端代码会被浏览器完整下载，写进去的任何东西都是公开的。如果把长期 AccessKey 放前端，等于把云账号钥匙贴在门口。正确做法：长期密钥只放服务端，服务端用它换一张"限时、限权"的临时凭证发给前端——就算泄漏，危害也被限制在 15 分钟 + 一个前缀 + 只能上传。

## 三、整体架构

```text
┌────────────────────────────────────────────────────────────────┐
│ 浏览器（Vue 3 前端，Netlify 静态托管）                            │
│  ImageUploader.vue ──▶ authorization.ts ──▶ upload.ts          │
└──────────────────────┬───────────────────────▲─────────────────┘
              ① POST /api/upload-credentials    │ ③ 临时凭证 JSON
                       ▼                        │   (Cache-Control: no-store)
┌────────────────────────────────────────────────────────────────┐
│ Netlify Function: get-upload-credentials.ts                    │
│  env.ts 校验环境变量 ──▶ sts.ts 调用阿里云 STS AssumeRole        │
└──────────────────────┬───────────────────────▲─────────────────┘
              ② AssumeRole(长期 AK)             │ ② 临时凭证(900s)
                       ▼                        │
              ┌─────────────────┐               │
              │   阿里云 STS     │───────────────┘
              └─────────────────┘

浏览器 ──④ ali-oss client.put(文件, 临时凭证)──▶ 阿里云 OSS
浏览器 ◀────────────── ⑤ 拼接公共读 URL ──────────────────────────
```

数据流要点：**图片文件从不经过 Netlify**，Function 只发凭证。服务器零文件流量。

## 四、一次上传的完整旅程

以拖入一张 `cat.png` 为例，按时间顺序：

1. **前端接收文件**（`ImageUploader.vue`）
   三种入口：点击选择、拖拽、Ctrl+V 粘贴（`extractPasteImages` 从剪贴板提取图片，重命名为 `paste-yyyyMMdd-HHmmss.<ext>` 后复用同一上传链路）。
   `validateImageFile` 校验类型/大小 → `URL.createObjectURL` 生成本地预览 → 状态置为 `uploading`。

2. **申请授权**（`src/services/authorization.ts`）
   检查内存缓存：若有凭证且距过期 >60 秒，直接复用；否则 `POST /api/upload-credentials`。

3. **服务端校验环境**（`netlify/functions/lib/env.ts`）
   从环境变量读取 6 个配置。任一缺失 → `500 SERVER_ENV_MISSING`，错误信息**只含变量名，绝不含值**。

4. **换取临时凭证**（`netlify/functions/lib/sts.ts`）
   用 RAM 用户长期 AK 调 STS `AssumeRole`（角色 `image-bed-uploader`，900 秒）。
   角色策略限定：仅 `oss:PutObject`、仅 `mirai-image-bed` 桶、仅 `uploads/*` 前缀。

5. **下发凭证**（`lib/upload-credentials.ts`）
   返回 `{ credentials, region, bucket, uploadPrefix }`，响应头 `Cache-Control: no-store`——临时凭证禁止被任何中间层缓存。

6. **浏览器直传 OSS**（`src/services/upload.ts`）
   用临时凭证构造 `ali-oss` 客户端，生成对象 key：
   `uploads/yyyy/MM/dd/<uuid>.png`（按日期归档 + UUID 防重名覆盖）→ `client.put` 上传。

7. **拼接公共 URL + 写入历史**
   `https://<bucket>.<region>.aliyuncs.com/<objectKey>`，展示为可点击链接，一键复制 URL / Markdown / HTML；
   同时 `historyStore.add` 把记录持久化到 localStorage（上限 100 条，见 ADR 0002），页面下方"上传历史"区块可再次复制链接或移除（仅删本地记录，不动 OSS）。

## 五、安全设计逐条

| 设计 | 防什么 |
|---|---|
| 长期密钥只在 Netlify 环境变量 | 仓库泄漏 / 前端构建产物泄漏 / 日志泄漏 |
| 临时凭证 900 秒过期 | 凭证被抓包后的长期滥用 |
| 仅 `oss:PutObject` + 限定 `uploads/` 前缀 | 越权删除、覆盖他人文件、列桶扫内容 |
| 对象 key 强制带前缀（服务端约束 + 前端生成） | 越权写任意路径 |
| 响应 `Cache-Control: no-store` | 临时凭证被 CDN/浏览器缓存后失控扩散 |
| 环境变量缺失显式 500，不静默降级 | 配置不全时产生难以排查的"半可用"状态 |
| 报错只含变量名不含值 | 错误日志成为密钥泄漏渠道 |
| Bucket 公共读、写不开放 | 图床 URL 可直接用，但匿名用户写不进东西 |

## 六、代码地图

```text
image-bed/
├── netlify/functions/
│   ├── get-upload-credentials.ts   # v2 薄入口：读 process.env，组装 handler
│   └── lib/
│       ├── env.ts                  # 环境变量校验（纯函数，注入来源）
│       ├── sts.ts                  # StsProvider 接口 + 阿里云实现 + mock 实现
│       └── upload-credentials.ts   # handler 工厂：405/500 错误处理，注入依赖
├── src/
│   ├── components/
│   │   ├── ImageUploader.vue       # 拖放区 + 粘贴上传 + 上传列表 + 状态反馈 + 复制
│   │   └── UploadHistory.vue       # 上传历史区块（缩略图、复制、移除本地记录）
│   ├── services/
│   │   ├── authorization.ts        # 授权客户端：凭证缓存 + 过期前 60s 自动续
│   │   ├── history.ts              # 上传历史：localStorage 读写（注入 Storage，异常降级为内存态）
│   │   └── upload.ts               # key 生成、URL 拼接、ali-oss 上传器 + mock
│   ├── utils/                      # file 校验/粘贴提取、clipboard、formats（纯函数）
│   └── types/image.ts              # 共享类型
├── tests/unit/                     # 10 个测试文件，63 个用例
├── doc/                            # 方案、契约、ADR、任务清单
├── AGENTS.md                       # 项目宪法：安全红线与开发流程
└── netlify.toml                    # 构建命令 / dist 发布目录 / functions 目录
```

**贯穿始终的设计手法：纯函数 + 依赖注入。** 核心逻辑（`env.ts`、`sts.ts`、`upload-credentials.ts`、`upload.ts`）都不直接读 `process.env` 或全局对象，而是让调用方把依赖传进来。所以每个模块都能用假环境、假 STS、假 fetch 做单测，44 个测试全部在 Node 里跑，不需要真实云资源。

**可替换实现：** `StsProvider` 和 `ImageUploader` 都是接口，各有"阿里云真实现 + mock 假实现"两份。开发前期前端对接 mock 链路，契约稳定后切换真实现，前端零改动。

## 八、踩坑与排查手册

| 现象 | 根因 | 解法 | 经验 |
|---|---|---|---|
| 本地正常，Netlify 上 500 "Client is not a constructor" | Tea SDK CJS 产物无 `__esModule` 标记，esbuild 打包后 default import 拿到 exports 对象 | `resolveStsClientCtor` 兼容 `.default` 与直接导出两种形态 | 本地通过 ≠ 生产通过，打包器改变模块解析行为 |
| `npm run dev` 起不来，EACCES | Windows Hyper-V/WSL 动态保留 5141–5240 端口段 | 换保留段之外的端口；`netsh interface ipv4 show excludedportrange protocol=tcp` 可查 | 开发环境起不来，先怀疑操作系统 |
| STS 报 `EntityNotExist.Role` | Netlify 环境变量里角色 ARN 粘贴错误 | 修正环境变量重新部署 | 报"不存在"先怀疑自己抄的配置值 |
| 上传返回 -1，无任何错误信息 | OSS Bucket CORS 未加 Netlify 域名，浏览器拦截 PUT | OSS 跨域设置追加站点域名，强刷浏览器缓存 | 静默失败的跨域请求先查 CORS；被拦的请求在服务端日志里"无事发生" |

## 九、配置清单

**Netlify 环境变量（6 个，仅服务端可见）：**

| 变量 | 用途 |
|---|---|
| `ALIBABA_CLOUD_ACCESS_KEY_ID` / `ALIBABA_CLOUD_ACCESS_KEY_SECRET` | RAM 用户长期密钥（仅用于 AssumeRole） |
| `OSS_REGION` | `oss-cn-shenzhen` |
| `OSS_BUCKET` | `mirai-image-bed` |
| `OSS_UPLOAD_PREFIX` | `uploads/` |
| `ALIBABA_CLOUD_STS_ROLE_ARN` | 角色 ARN（格式 `acs:ram::<账号ID>:role/image-bed-uploader`） |

**阿里云侧配套：** RAM 用户（仅需 `AliyunSTSAssumeRoleAccess`）、角色 `image-bed-uploader`（策略限定桶 + 前缀 + PutObject）、Bucket 公共读、CORS 放行 Netlify 域名与本地开发地址。
