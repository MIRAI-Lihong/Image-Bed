# ADR 说明

ADR 是 Architecture Decision Record，用于记录“为什么这样定”。

当某个决策满足以下任一条件时，应新增或更新 ADR：

- 会长期影响代码结构或部署方式
- 涉及安全边界、权限模型或数据访问方式
- 存在多个可选方案，且已经完成取舍
- 后续成员如果不知道背景，容易误改或重复讨论

## 文件命名约定

- 采用递增编号，例如 `0001-project-foundation.md`
- 文件名使用英文短语，方便排序和检索

## 推荐结构

每个 ADR 建议包含以下部分：

1. 标题
2. 状态
3. 背景
4. 决策
5. 影响
6. 后续事项

## 使用方式

- 决策确认后尽快补 ADR，不要等到实现结束再回填
- 如果原有决策被推翻，不要直接删除旧 ADR，应新增一个后续 ADR 说明替代关系
