# ADR 0002：上传历史使用 localStorage 本地存储

## 状态

已确认

## 背景

V1 收尾需要增加"上传历史记录"功能（任务 7）：上传成功后把图片 URL、文件名、大小、时间保存下来，刷新页面后仍可查看和复制。

方案文档（`doc/personal-image-host-plan.md`）预留了两个候选：localStorage 或 IndexedDB，需要在实现前完成取舍。

历史记录的特点：

- 每条记录仅约 200 字节（URL + 对象 key + 文件名 + 大小 + ISO 时间）
- 上限 100 条，总量约 20KB
- 读写频率极低：仅上传成功时写一次，页面加载时读一次
- 无复杂查询需求：按时间倒序展示即可，搜索筛选留给后续阶段

## 决策

采用 **localStorage**，不引入 IndexedDB。

### 存储结构

- key：`image-bed:history`（带命名空间，避免与同域其他应用冲突）
- value：JSON 序列化的记录数组，按上传时间倒序（新记录在前）

```json
{
  "version": 1,
  "items": [
    {
      "id": "ulid-or-uuid",
      "url": "https://<bucket>.<region>.aliyuncs.com/uploads/2026/10/11/uuid.png",
      "objectKey": "uploads/2026/10/11/uuid.png",
      "fileName": "cat.png",
      "size": 102400,
      "uploadedAt": "2026-10-11T08:30:00.000Z"
    }
  ]
}
```

- `version` 字段用于未来结构变更时的迁移判断
- 上限 100 条，追加后超出部分从末尾淘汰
- 不存 `previewUrl`（objectURL 刷新后失效），缩略图直接引用公共读 URL

### 异常处理

- localStorage 不可用（隐私模式、配额满、用户禁用）时静默降级：上传功能不受影响，历史功能表现为"始终为空"
- 读取时 JSON 解析失败视为空历史，不抛错

### 职责边界

- 移除历史记录**只删本地数据，不删除 OSS 对象**（ADR 0001 已定首版不给前端删除权限）
- 记录只属于当前浏览器；清理浏览器数据或换设备后记录丢失，OSS 图片不受影响

## 影响

- 读写实现为同步 API，封装简单，无需引入任何依赖
- 测试沿用项目 DI 风格：注入 `Storage` 接口，单测中用内存假实现
- 若未来需要存储缩略图二进制、大量记录或复杂查询，再评估迁移 IndexedDB；`version` 字段保证了迁移可行性

- 任务 7 实现时按本文档的数据结构执行
- 若后续加入"搜索筛选"或记录量级上调，重新评估选型
