# ADR 0001：项目基础方案

## 状态

已确认

## 背景

项目目标是从零开发一个个人图床工具，并采用 Harness Engineering 的方式进行 AI 辅助开发。

当前阶段优先建设工程基础，而不是直接堆叠业务功能，因此需要尽早固定一组能够支撑后续开发的核心决策，避免在规则、目录、权限边界和交付方式上反复摆动。

## 决策

### 技术栈

- 前端采用 Vue 3 + TypeScript + Vite
- 图片存储采用阿里云 OSS
- 部署平台采用 GitHub + Netlify
- 服务端授权采用 Netlify Functions + 阿里云 STS

### 权限与访问

- OSS Bucket 采用公共读，用于生成可长期访问的图片 URL
- 上传写入通过 Netlify Functions 签发 STS 临时凭证完成
- 首版 STS 凭证只开放上传相关动作，不开放删除能力
- 长期密钥仅保存在 Netlify 环境变量中

### 工程策略

- 首批不引入 UI 组件库
- 首批不接入 GitHub Actions
- 规则自动加载入口使用根目录 `AGENTS.md`
- 架构说明、ADR 和运行手册统一放在 `doc/` 目录下维护

## 影响

- 前端页面和交互需要使用原生 Vue 组件自行组织
- 发布前的质量验证先依赖本地命令和 Netlify 构建结果
- 图片 URL 可以直接用于 Markdown、README 等公开场景
- 必须额外重视上传权限、对象前缀约束和 OSS CORS 配置

## 后续事项

- 在后续任务中补齐类型检查、Lint、测试和构建的统一验证入口
- 在服务端函数落地前补充环境变量清单和校验方案
- 在接入真实 OSS 前补充 CORS 和 STS 策略检查手册
