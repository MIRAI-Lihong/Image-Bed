# 项目基础约束

本文档描述当前仓库的工程基线，方便后续任务在同一套边界内推进。

## 1. 工程目标

当前阶段的重点不是尽快堆叠业务功能，而是先建立一个：

- 可维护
- 可验证
- 有清晰安全边界
- 能支持后续 AI 辅助迭代

的项目底座。

## 2. 目录职责

当前目录职责约定如下：

- `src/`
  - 前端应用源码。
- `src/features/`
  - 按业务能力划分功能模块，首版以 `upload` 为核心。
- `src/components/`
  - 可复用的通用展示或交互组件。
- `src/services/`
  - 与外部系统交互的逻辑封装，例如 OSS 或服务端接口。
- `src/types/`
  - 项目共享类型定义。
- `src/utils/`
  - 不直接依赖 UI 的通用工具函数。
- `netlify/functions/`
  - Netlify Functions 服务端入口。
- `tests/unit/`
  - 单元测试与轻量组件测试。
- `tests/integration/`
  - 跨模块或前后端契约层面的集成测试。

## 3. 当前不做的事情

为了控制复杂度，当前阶段先不做以下内容：

- 不引入 UI 组件库
- 不引入 GitHub Actions
- 不引入数据库
- 不实现图片删除
- 不把图片上传流量中转到 Netlify Functions

## 4. 安全边界

- OSS Bucket 为公共读，用于长期访问图片 URL
- 写入操作不能开放给匿名用户
- 前端只能获取受限的 STS 临时凭证
- 长期密钥只允许保存在 Netlify 环境变量
- 上传对象必须限制到约定前缀，避免覆盖任意对象

- 架构取舍：新增 `doc/adr/*.md`
- 人工操作步骤：更新 `doc/runbooks/*.md`
