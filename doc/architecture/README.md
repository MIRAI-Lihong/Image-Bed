# 架构文档说明

本目录用于存放项目级架构说明，重点回答以下问题：

- 当前工程的结构和职责如何划分
- 哪些文档会被 Trae 自动加载，哪些只作为人工参考
- 当前版本已经确认的关键技术决策是什么

## 文档边界

- `AGENTS.md`
  - 这是项目级自动加载规则文件。
  - 只放需要持续生效的开发规则、安全红线、验证要求和当前已确认的强约束。
- `doc/architecture/*.md`
  - 用于补充架构说明、职责划分、术语和实施边界。
  - 这些文件不会被 Trae 自动加载，应视为人工阅读和评审材料。
- `doc/adr/*.md`
  - 用于记录有取舍成本的架构决策。
  - 决策一旦落地，应在对应 ADR 中说明背景、结论和影响。
- `doc/runbooks/*.md`
  - 用于记录需要人工执行的操作手册和检查清单。
  - 例如环境变量配置、OSS CORS 检查、部署前检查等。

## 文档优先级

从“约束力”角度看，当前项目建议按以下顺序理解：

1. Trae 平台和系统级约束
2. 根目录 `AGENTS.md`
3. 用户在当前任务中明确给出的要求
4. `doc/adr/*.md` 中已经确认并落地的架构决策
5. `doc/architecture/*.md` 与 `doc/runbooks/*.md` 中的说明文档

## 当前已确认决策

- 前端采用 Vue 3 + TypeScript + Vite
- 图片存储使用阿里云 OSS
- Bucket 采用公共读，图片 URL 需要可长期访问
- 上传写入通过 Netlify Functions + 阿里云 STS 临时凭证进行受控授权
- 首批不引入 UI 组件库
- 首批不接入 GitHub Actions

## 维护要求

- 新增会长期影响实现方式的决策时，优先新增 ADR，再更新相关说明文档
- 仅影响某次任务操作流程的说明，写入 `doc/runbooks`
- 不要把普通说明文档当作自动加载规则使用
